# PR C · ui/tests-history-compare — tests catalog, editor, test page, compare

Branch `ui/tests-history-compare` · base main (after A merges) · depends on A ui/foundation · backend TH-07 (current vs shown version in the history read model) · size 1–2 weeks.

Read `docs/ui-migration/README.md` first: it holds the rules every UI PR follows and the verification recipe. This brief lists what this PR closes; the audit reports (`docs/ui-migration/reports/`) hold the full finding text and the screenshots each one cites.

## Scope

Four surfaces, in this order:

1. **Tests catalog** (`pages/TestsCatalogPage.tsx`) — `DataTable` grouped by lifecycle, `FilterChip` filters with state in the URL, "retired" collapsed, cursor pagination, sorting. Keep the wave-1 behaviour (row link, executions across versions, source filter).
2. **Test editor** (`components/LocalScenarioEditor.tsx`) — two columns with live Markdown, per-field validation, compact criteria with the running sum, post-creation toast with actions. Keep the wave-1 behaviour (empty draft, derived file name, fixed footer, discard confirmation).
3. **Test page** (`pages/TestHistoryPage.tsx`) — unifies history and compare: identity header with the honest version (contract vs shown), tiles only with data, trend always visible, A/B by checkbox with a fixed bar, actionable empty state, drawer instead of a translucent modal, "passed" in green, Cost column hidden without data, state in the URL.
4. **Compare** (`pages/TestsPage.tsx`) — explicit builder (cohort, A, B with date and counts), default filter "with evidence", KPIs bound to the table, one row per side per state with a directional signed Δ (`DeltaValue`), hash kept in sync, link to the history.
