### Oportunidades de redesenho

- **Card "one-glance"**: linha (nome mono lowercase · `StatusBadge` objetivo · advisory · runtime · *why* em uma frase) e expansão inline em dois blocos fixos — "why it failed" (diagnóstico + next step + link direto para o gate/assessment que falhou) e "assessment matrix" (tabela real com chips de filtro que filtram as linhas). As ações transcript / chat / evidence record vão para o header da expansão. Elimina os três níveis atuais (`<details>` → botão → diálogo) e os cinco níveis de borda.
- **Evidence record como rota** (`#/ext/harness-e2e/execution/<id>/run/<runId>`) em vez de `<dialog>`: URL compartilhável, resolve o link `#technical` (AW-01), acaba com scroll dentro de scroll (AW-08) e com o diálogo full-screen improvisado no 390 (RD-01). O diálogo atual só sobreviveria como preview.
- **Transcript como drawer lateral ou rota**: coluna única com rail de papéis, timestamps, busca, copiar e tool calls compactos; abrir a partir do card e do evidence record com o evento de erro já focado.
- **Uma só primitiva de status**: `StatusBadge` (ponto + mono) para linha, card, diálogo e "outcome boundaries"; aposentar pílulas `rounded-full`, `StatusCard` com fill rosa e `PrimaryMetricBoard` colorido. Um único helper de nome (`humanize`) e um único botão (DS).
- **Matriz de verdade quando há muitos cenários** (hard gate tem 6): `<table>` ordenável (por status/runtime), filtro "only failed", coluna "Structure" só quando existir workflow; `SemanticTestFlow` reescrito como tabela de passos, e só depois de existir uma fixture com `semantic_tests`.
