# PR D · ui/overview-executions-evidence — overview, executions ledger, execution detail, evidence route, coverage

Branch `ui/overview-executions-evidence` · base main (after A merges) · depends on A ui/foundation · backend E-12 (cursor pagination and `cancelling` state) and CV-01 (coverage summary through the bridge) · size 1–2 weeks.

Read `docs/ui-migration/README.md` first: it holds the rules every UI PR follows and the verification recipe. This brief lists what this PR closes; the audit reports (`docs/ui-migration/reports/`) hold the full finding text and the screenshots each one cites.

## Scope

Four surfaces, in this order:

1. **Overview** (`pages/OverviewPage.tsx`) — a signal panel: latest execution, deltas and trend, attention queue, running, five recent. Coverage becomes two `MetricCard`s fed by the bridge, or the route is removed (decision recorded in the PR).
2. **Executions ledger** (`pages/OverviewPage.tsx`, executions view) — cursor pagination, grouped by day, running pinned, `subscribeRunChanges`. Keep the wave-1 behaviour (filters in the column vocabulary, row links).
3. **Execution detail** (`pages/ExecutionPage.tsx`, `components/ScenarioMatrix.tsx`, `AssessmentWorkspace.tsx`) — identity header in one band, aggregated verdict per execution, "why it failed" on the scenario row, filters with real counts, provenance collapsed, dedicated running/cancelled states, section bar bound to anchors.
4. **Evidence route and transcript** (`components/TranscriptDialog.tsx`, `ScenarioChatAction.tsx`, `SemanticTestFlow.tsx`) — evidence record as a route (`execution/<id>/run/<runId>`), transcript as a drawer with a role rail, timestamps, search and copy; `SemanticTestFlow` returns only with a fixture. Then remove `reload()` from the standalone router and `useLegacyPage`.
